# BATCAVE 1.0 — отчёт о проверке

Дата: 9 октября 2026. Результат: **15 unit-тестов и 8 браузерных сценариев прошли**, TypeScript и production-сборка проходят. Проверка production-зависимостей `npm audit --omit=dev` не обнаружила известных уязвимостей на момент выполнения.

## Среда

Node.js 24.19.0, Chromium 153.0.8010.0 под Playwright. Мобильная эмуляция: touch, viewport 375×812, DPR 3. Дополнительно проверены ширины 320, 375 и 390 px. Сайт обслуживался как готовая production-сборка по адресу `http://127.0.0.1:4173/batcave-reader/`, с реальным service worker и IndexedDB. Это проверка мобильного интерфейса в Chromium, не физического iPhone и не Safari/WebKit.

## Unit-тесты: 15/15

- Начальная инициализация не дублирует каталог; 11 произведений, 2 бумажных экземпляра, 8 непроверенных статусов бумаги.
- Статистика не содержит вымышленных страниц, времени или оценок.
- Прогресс считает разные открытые страницы, а не номер страницы после прыжка.
- Естественная сортировка `1.png`, `2.png`, `10.png`.
- Проверка содержимого файла: PDF, изображения, отказ переименованному RAR, неверному расширению и пустому файлу.
- Чтение центрального каталога CBZ без распаковки всей книги.
- Отказ повреждённому архиву, архиву без изображений, слишком большим и зашифрованным страницам.
- Сохранение оригинала и прогресса, отсутствие повторного учёта страницы, автоматический статус после открытия всех страниц.
- Удаление оригинала освобождает соответствующее вложение и сохраняет актуальный прогресс; удаление записи удаляет её вложения.
- Проверка схемы резервной копии, версии, дублирующихся ID, путей и границ прогресса.
- Политика конфликта: сохранение текущей записи по умолчанию, явная замена.
- JSON без оригиналов не создаёт фиктивные цифровые копии.
- SHA-256 и отказ ZIP, который не является копией BATCAVE, без изменения базы.
- Проверка размеров PNG до декодирования, отказ изображениям сверх лимита.
- Отказ изображению без корректного заголовка размеров.
- Проверка размеров и сигнатур JPEG и WebP.

Некоторые пункты объединены в один тест. Исходники тестов: `tests/unit/core.test.ts`.

## Сохранность и производительность

PDF не преобразуется целиком в изображения. Используются диапазоны Blob по 64 КБ и отдельный worker. CBZ хранится оригинальным архивом; страницы извлекаются по запросу. В одиночном режиме один холст; в вертикальном — до пяти. Ограничение вывода — 4 млн пикселей на холст. Обложки, URL, рендеры и reader-ресурсы освобождаются при закрытии.

Форматы, схемы и SHA-256 проверяются до транзакции восстановления. Полная копия ограничена 300 МБ; оригинальный импорт — 600 МБ. Для экспортированного файла предусмотрена отдельная кнопка «Сохранить копию», если Safari не запускает загрузку после асинхронной подготовки.

## Известные ограничения и непроведённые проверки

- Физический iPhone, установка и работа Safari/WebKit на устройстве здесь не проверялись. Автоматическое скачивание WebKit было недоступно в окружении; Chromium был запущен из отдельно доступного пакета.
- Публичный репозиторий, запуск GitHub Actions на аккаунте и публичная Pages-ссылка не создавались и не проверялись. Пользователь выбрал самостоятельную загрузку ZIP. Workflow подготовлен по актуальной документации GitHub; его нужно запустить после включения Pages.
- Файл на 600 МБ и полный архив на предельные 300 МБ не тестировались. Тест на 400 страниц проверяет виртуализацию, а не гарантирует отсутствие нехватки памяти на каждом устройстве.
- Лимит: 5000 страниц, 32 МБ на страницу CBZ, 2 ГБ распакованного объёма архива и 32 мегапикселя на изображение. Повреждённые поздние страницы обнаруживаются по мере чтения; весь оригинал при импорте не распаковывается для тотальной проверки.
- CBR, RAR, зашифрованные PDF/ZIP, DRM, автопрокрутка и синхронизация не реализованы. CBR/RAR и защищённые файлы отклоняются с объяснением.
- iOS может очистить хранилище. «Устойчивое хранение» зависит от решения браузера и не отменяет необходимости резервных копий.
- Время — оценка видимой активности с паузой после двух минут без действий. «Открыто страниц» не равнозначно доказанному прочтению. При принудительном закрытии возможна потеря нескольких последних секунд таймера.
- Одновременное редактирование одной записи в разных вкладках не имеет интерфейса разрешения конфликтов; используйте одну активную вкладку/PWA для коллекции.

## Проверка после публикации на iPhone

1. Открыть публичную Pages-ссылку в Safari, установить на экран «Домой».
2. Запустить с иконки и дождаться «Офлайн готов» в настройках.
3. Импортировать свой PDF и CBZ из «Файлов», открыть несколько страниц, увеличить и переместить страницу.
4. Закрыть PWA, открыть снова, проверить страницу и файл.
5. Включить авиарежим и повторить чтение.
6. Экспортировать полный архив в «Файлы». Не удаляя исходную библиотеку, проверить восстановление на другом браузере/устройстве.
