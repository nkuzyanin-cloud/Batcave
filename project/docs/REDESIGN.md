# BATCAVE 1.2 — минималистичный интерфейс

Обновление существующего приложения. База IndexedDB `batcave-reader`, её версия 1, имена object stores и идентификаторы пользовательских файлов сохранены. Публикация выполняется пользователем через существующий репозиторий GitHub Pages: выбран ZIP.

## Что изменено

- Шапка 52 px плюс safe-area, симметричный SVG-бэтаранг, название и настройки. Удалены подпись архива и точка.
- Первый запуск пустой: нет автоматического каталога и бумажных изданий.
- Библиотека: две обложки в ряд на телефоне, название и тонкий прогресс. Поиск и фильтры компактны; сортировка и группировка перенесены в небольшое меню. Продолжение появляется только после чтения, высота около 86 px.
- Коллекция показывает записи, которые пользователь отметил как имеющиеся в бумаге. Нет фильтров библиотеки и текста про сов. Подтверждённые объединённые тома по-прежнему считаются одним физическим экземпляром.
- Профиль: четыре компактных показателя, небольшой прогресс, три компактных достижения, личные оценки. Объяснение статистики раскрывается по запросу.
- Карточка книги открывается как нижний лист. Основные поля сразу доступны, дополнительные сведения и фото раскрываются отдельно. Кнопка сохранения закреплена при прокрутке. Создание бумажной записи начинается с пустого названия.
- Короткие переходы и реакции на нажатия сохраняют настройку уменьшения движения.
- Обновлены SVG и PWA-иконки. Читалка сохранена: её исходник идентичен поставленному BATCAVE 1.0. Отменённый режим чтения по областям не включён.

## Миграция данных

При первом запуске обновления удаляются только записи с зарезервированными стартовыми ID `dc-*`, точным совпадением всех исходных значений и характерной исходной разницей временных меток. Сравниваются также дополнительные неизвестные поля: их наличие сохраняет запись.

Любой оригинальный файл, ссылка на фото/обложку, прогресс, оценка, заметка, изменение метаданных или временной подписи сохраняет запись. Неуверенные кандидаты остаются. Миграция выполняется одной транзакцией и отмечается отдельным ключом конфигурации. Она не изменяет и не удаляет assets и настройки. Восстановленные пользователем записи после этой миграции повторно автоматически не очищаются.

Коллекция стала отдельной полкой: цифровые книги без подтверждённого бумажного экземпляра видны в библиотеке. Это фильтрация отображения, а не удаление записей.

## Проведённые проверки

- TypeScript и production build проходят.
- 17 unit-тестов проходят: форматы, сортировка CBZ, пределы изображений, IndexedDB, резервные копии, а также консервативная миграция.
- 10 функциональных браузерных сценариев и сценарий создания скриншотов проходят в Chromium с touch-профилем iPhone 13 Mini.
- PDF: импорт, показ страниц, свайп, двойное касание, pinch, сохранение страницы после перезапуска, удаление цифрового файла с сохранением карточки.
- CBZ: импорт, естественная сортировка, дубликаты, повреждённые/пустые архивы, виртуализация 400 страниц, чтение после офлайн-перезапуска.
- JSON/ZIP: экспорт, проверка CRC/SHA-256, отклонение повреждённой копии без изменения библиотеки, восстановление в пустом хранилище, конфликты.
- Бумажная полка: создание, изменение, оценка, фото, сохранение, сброс прогресса и удаление с подтверждением.
- Миграция существующей базы: импортированный PDF на странице 3, оригинал, фото, оценка и заметка бумажной книги, RTL, выключенные анимации и графитовый фон сохраняются. Проверка байтов оригинала выполнена в unit-тесте, размер и чтение — в браузерном.
- На ширинах 320/375/390 px две колонки и нет горизонтального переполнения. Без блока продолжения первая обложка начинается выше 240 px; карточка продолжения ниже 90 px по высоте.
- Manifest, относительные пути, service worker и работа в `/batcave-reader/` проверены.
- После последней правки формы повторно проверены создание/редактирование полки, компактность библиотеки и создание скриншотов. Ошибок pageerror при съёмке нет.

Фактические скриншоты 375×812 находятся в `docs/screenshots/redesign/`. Они сняты в работающем браузере; на заполненных экранах используются явно обозначенные тестовые файлы. Эти записи не добавляются пользователю. Первый запуск показан отдельно. При съёмке уменьшение движения включено, чтобы снимки не фиксировали промежуточную прозрачность переходов.

## Ограничения

Физический iPhone и Safari/WebKit здесь не проверены. Публичная публикация не выполнялась: пользователь выбрал самостоятельную загрузку ZIP. CBR, DRM, синхронизация и гарантированное устойчивое хранение не добавлены. iOS может очистить локальное хранилище; резервные копии по-прежнему нужны. Сохранённые неоднозначные старые записи при необходимости удаляются вручную, с подтверждением.
