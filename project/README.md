# BATCAVE 1.0

Рабочая PWA для личного чтения и коллекционирования комиксов DC. PDF, CBZ, JPG, PNG и WebP. Комиксы, фото, заметки и прогресс сохраняются локально в IndexedDB. Нет серверной базы, аккаунтов, аналитики или загрузки пользовательских файлов в интернет.

## Запуск на GitHub

Архив уже содержит **готовый сайт в корне**, исходники в папке `project` и workflow `.github/workflows/pages.yml`.

1. Создайте публичный репозиторий **batcave-reader** с веткой `main`.
2. Распакуйте ZIP. Загрузите **всё содержимое архива** в корень репозитория, включая `project` и `.github`. Сам ZIP GitHub автоматически не распаковывает.
3. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Во вкладке **Actions** запустите **Build and publish BATCAVE → Run workflow**. При следующих изменениях в `main` сборка, тесты и публикация запускаются автоматически.
5. После успешного workflow ссылка появится в **Settings → Pages**. Обычный адрес: `https://ВАШ-ЛОГИН.github.io/batcave-reader/`.

Workflow собирает исходники `project`, проверяет TypeScript, запускает unit- и браузерные тесты и публикует `project/dist`. Для первого запуска выберите Pages Source до ручного старта workflow.

**Если загружаете с iPhone и не удаётся передать скрытую папку `.github`:** готовый сайт также работает при **Pages → Source → Deploy from a branch → main → / (root)**. Тогда GitHub публикует уже собранные файлы корня. Чтобы включить автоматическую сборку из исходников позже, создайте файл `.github/workflows/pages.yml` через **Add file → Create new file**, вставив содержимое `project/docs/pages-workflow.yml`, и переключите Pages Source на GitHub Actions.

В корне репозитория должны находиться `index.html`, `assets`, `icons`, `pdf`, `manifest.webmanifest` и `sw.js`. Не загружайте дополнительную внешнюю папку `BATCAVE-1.0` поверх них. Если репозиторий уже существует, сначала сохраните его содержимое и проверьте изменения; приложение не требует удаления репозитория или очистки локальной библиотеки.

## Установка на iPhone

Откройте **опубликованный сайт в Safari → Поделиться → На экран Домой**. Запустите BATCAVE с иконки. В настройках дождитесь **«Офлайн готов»**, затем добавляйте комиксы из приложения «Файлы».

Фактическая установка на физический iPhone и публичный деплой в этой сессии не выполнялись: пользователь самостоятельно загружает архив на GitHub. Chromium с мобильным viewport проверен; Safari/WebKit на устройстве нужно проверить после публикации.

## Как пользоваться

- **Библиотека:** поиск по названию, авторам и серии; фильтры; сортировка; группировка по сериям.
- **Добавить комикс:** выбирает один PDF, CBZ или файл изображения. Превью первой страницы, метаданные, полный SHA-256 для дубликатов. К карточке из начального каталога файл прикрепляется через **Добавить файл**.
- **Чтение:** свайпы, двойное касание и pinch для масштаба; перетаскивание увеличенной страницы. В вертикальном режиме — прокрутка, двойное касание, pinch и прокрутка увеличенной картинки внутри страницы. Касание скрывает интерфейс. Ползунок и кнопки меняют страницу. Направление свайпов настраивается отдельно; кнопки «Следующая/Предыдущая» всегда идут по номеру страницы.
- **Коллекция:** независимые статусы бумаги и чтения, оценка, издание, издательство, заметка, фото. Кнопка «Добавить» здесь создаёт бумажную запись без файла. Можно учитывать любые комиксы DC.
- **Профиль:** реальные показатели архива. «Открыто страниц» означает разные успешно показанные страницы; это не доказательство их прочтения. Время чтения — оценка активности.
- **Настройки:** режим чтения, анимации, управление файлами, JSON, полный ZIP, восстановление, сброс прогресса с подтверждением.

Начальные 11 произведений содержат только метаданные. «Суд Сов» и «Город Сов» — один подтверждённый бумажный экземпляр. «Возвращение Тёмного рыцаря» — второй. Остальные бумажные издания не проверены. Коммерческих страниц в сборке нет.

## Резервные копии

**JSON:** коллекция, настройки, прогресс. Без оригиналов, обложек и фото. Восстановление JSON в новую библиотеку не создаёт фиктивных цифровых файлов: оригиналы надо добавить отдельно.

**Полный ZIP:** оригиналы, обложки, фото и метаданные; до 300 МБ данных. Файлы проверяются по SHA-256. Архив сначала полностью проверяется, затем изменения записываются одной транзакцией. При совпадении ID или файла по умолчанию остаются текущие данные; отсутствующий оригинал возвращается. Можно явно заменить совпадающие записи и восстановить настройки. Остальные записи сохраняются.

iOS может очистить IndexedDB. Экспортируйте копии в «Файлы» или на компьютер. Safari, установленная PWA, другой браузер, другой домен и другое устройство могут иметь отдельное хранилище — переносите данные резервной копией. Запрос устойчивого хранения в настройках не гарантирует сохранность.

## Ограничения

- CBR / RAR и защищённые паролем файлы не поддерживаются. Переименование в CBZ не конвертирует CBR.
- Импорт до 600 МБ, до 5000 страниц; страница CBZ до 32 МБ, распакованный объём архива до 2 ГБ. Изображение до 32 мегапикселей. Реальная доступность памяти и места зависит от устройства.
- Полный ZIP до 300 МБ; для большей библиотеки сохраняйте JSON и оригиналы отдельно.
- Все страницы проверяются по мере открытия; импорт проверяет структуру и первую страницу. Повреждение поздней страницы обнаружится при чтении.
- Встроенная полноэкранная читалка работает и без браузерного Fullscreen API. На iPhone лучший полноэкранный режим — установленная PWA; Safari может оставить системную панель браузера.
- Таймер сохраняется примерно каждые 5 секунд, останавливается в скрытой вкладке и после 2 минут без действий. Возможна потеря нескольких последних секунд при принудительном завершении.
- Нет DRM, синхронизации между устройствами, автопрокрутки и CBR. Текущая версия рассчитана на актуальный Safari; старые версии браузеров отдельно не проверялись.

## Разработка

```bash
cd project
npm ci
npm run dev
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

Node.js 24. В `project/dist` получается самостоятельный сайт. В Actions публикуется эта папка; готовые файлы корня архива нужны для первоначальной ручной публикации. Изменения исходников не обновляют корневую ручную сборку сами по себе — используйте Actions или скопируйте новую `project/dist` в корень.

Подробнее: `project/docs/ARCHITECTURE.md`, `project/docs/CATALOG.md`, `project/docs/TEST_REPORT.md`. Фактические снимки интерфейса находятся в `project/docs/screenshots`.
